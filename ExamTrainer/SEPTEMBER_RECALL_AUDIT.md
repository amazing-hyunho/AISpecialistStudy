# 2026-09 복기 기반 전체 재점검

근거는 사용자가 제공한 시험 복기와 현재 강의 노트북이다. 공식 시험 원문/정답지나 다음 시험 출제 예측으로 취급하지 않는다.

## 방향 수정

이번 복기는 수식만 암기하기보다 **shape 설명 → 축 선택 → Tensor 연산**, **설정 → 레이어 생성**, **입출력 → 실행 흐름 연결**의 중요성을 보여 준다.
기존 기출 이야기를 바탕으로 DPO·LoRA·복잡한 RAG에 우선순위를 둔 구성은 이번 실제 경험과 차이가 있었다.
수식이 영구적으로 제외된다고 일반화하지는 않으며, PDF의 기존 학습·평가·경량화 범위도 보존한다.

| 과목 | 기존 포함 | 누락 및 보강 |
| --- | --- | --- |
| LLM | QKV 투영·점수, 임베딩 합산, out_head, no_grad, 마지막 시점·argmax·cat | **MHA class 셀 자체가 빠졌음.** 089~093: 헤드 분리·축 이동·재결합. 094: MultiHeadAttention 생성. 095: model(idx_cond) |
| RAG | from_documents, role/content 메시지 | 029: as_query_engine. 복잡한 검색 외 기본 API 조합도 모의고사에 반복 |
| Data | EncoderRNN/DecoderRNN 정의·학습 루프 | 034~042: 입력/타깃 슬라이싱, float32 구성, RNNRNN의 encoder 상태·초기 입력·한 스텝·출력 저장·재입력·stack |
| Vision | crop/flip/ToTensor, Attention residual | 035~037: FFN residual, 학습 Normalize, Compose. 학습 전처리의 누락된 조각을 채움 |
| On-device | 원소 단위 magnitude pruning | 061~064: 입력 채널 수·제거 수·중요도 합산·mask 확장. 원소 단위와 채널 단위를 구분 |

24문제 추가: LLM 95 / RAG 29 / Data 42 / Vision 37 / On-device 64 = 267문제.
원문 셀 기반 255문제 + 기존 재구성 DPO 12문제. 재구성 DPO는 모의고사에서 계속 제외한다.
기존 정답과 ID는 유지한다. 신규 문제는 복기·shape 중심 선별이며 원본 빈칸이라고 단정하지 않아 별표를 붙이지 않는다.

## 모의고사와 복습

- 고정 10회는 계속 과목별 2셀, 회차마다 10셀이다. 1·2·9·10회를 복기 우선으로 재편했다.
- 1·9회: MHA·GPT 생성/출력, 기본 RAG, 시계열 창+RNNRNN, transform+residual, 채널 프루닝.
- 2·10회: MHA 생성자, query engine/messages와 같은 설정·API 구성을 반복한다.
- 나머지 회차에는 기존 학습, 데이터, KG·MCP, 양자화·증류 범위를 남긴다.
- 셀마다 코드 순서대로 작성 가이드를 표시한다. 신규 가이드에는 입력/출력 shape와 수행할 연산이 포함된다.
- 랜덤 모의고사에도 추가된 실제 셀이 자동 포함된다.
- 최종 핸드북의 앞 5항목도 이번 복기 방향으로 수정하고 기존 14개는 보충 범위로 유지했다.

## 원문을 보존하면서 알리는 주의점

- 시계열 창 생성의 range는 원문의 `len(data)-sequence_length-target_len`을 유지했다. 모든 가능한 마지막 창을 포함하려는 구현에서는 +1 경계를 검토할 수 있다. 새로운 정답으로 조용히 교체하지 않았다.
- 채널 프루닝의 `(0,2,3)` 합산은 입력 채널 축을 남긴다. 출력 채널 pruning과 다르다.
- 작은 sparsity에서 round 결과가 0이면 원문의 kthvalue(k=0)가 실패할 수 있다. threshold 동률도 실제 제거 수에 영향을 준다. 이 연습은 해당 함수가 모든 경계에서 안전하다는 보장이 아니다.
- mask를 곱해 0으로 만드는 것과 구조적으로 채널을 제거해 연산량을 줄이는 것은 다르다.
- 복기의 TODO는 실제 구현 요구일 수 있다. TODO라는 문자열만으로 무조건 제외하지 않지만, 이번에는 원본에 정답 코드가 있는 연산만 새 문제로 채택했다.

## 재생성·검증

기존 과목 생성기를 실행했다면 **마지막에** `python scripts/supplement_september_recall.py`를 실행한다.
보강 스크립트는 안정적인 ID로 upsert하고, `recall-explanations.json`을 생성한다. 반복 실행 결과는 동일하다.
Study 원본을 수정하지 않으며 서버 주소·키가 포함된 새 셀은 사용하지 않는다.

`audit-bank.cjs`: 전체 ID·출처 노트북의 해당 코드 셀·정답 문자열·빈칸 겹침·TODO 답안을 검사한다.
`test-inline-quiz.cjs`: 500회 랜덤 추첨 및 고정 10회의 구성·재시작·채점 회귀검사.
RAG/Vision 원문·해설 및 최종 핸드북 검사도 수행한다. 로컬에 torch가 없어 전체 모델 실행 검증은 하지 않았으며 코드 위치/구성 검증과 구분한다.
