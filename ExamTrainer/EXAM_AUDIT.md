## 결론

현재 문제는 **강의 코드 재현·암기 연습**으로 대체로 타당하다. PDF가 요구하는 원리 이해 전부를 검증하는 시험, 실제 시험의 출제 확률, 동작이 같은 모든 답안을 인정하는 실행 채점기로 해석하면 안 된다.
문제를 일괄 삭제하거나 새로 늘리지 않고 전체 243문제의 주제·답안을 검토하고 출처·빈칸 위치를 검사했다.

## 확인한 결함과 조치

`dpo-completions`는 원본의 서로 다른 작성 구간을 결합하고 힌트에 따라 채운 재구성 예제다. 이를 원본 노트북의 Cell 0으로 취급하던 출처 표시가 부정확했다.

- 관련 12문제는 기존 복습과 진행 기록 보존을 위해 유지했다.
- `sourceKind: reconstructed`를 명시하고 학습 화면·핸드북에 재구성 예제임을 표시했다.
- 실제 원본 셀을 뽑는 모의고사 후보에서는 제외했다.
- 나머지 231문제는 명시된 출처 노트북의 해당 코드 셀에서 정답 문자열을 확인했다. 재구성 예제의 12개 답을 강의 답안 원문이라고 보증하지 않는다.

## 타당성의 한계 (삭제하지 않은 이유)

- `llm-017/018`, `vision-017`, `ondevice-020` 같은 rank·alpha·guidance·희소도 설정값은 보편적인 유일 정답이 아니다. 강의 설정을 외우는 문제로는 가능하지만 원리 이해의 증거로는 약하다. 원본 작성 구간/기존 사용자 요청을 보존했다.
- `rag-014`, `llm-030` 등 import·단일 변수 문제는 독립 문제로는 변별력이 낮다. 셀 전체에서 API·데이터 흐름을 읽는 맥락으로 활용한다.
- 코드에 들어 있는 주석과 주변 코드는 힌트가 될 수 있다. 원문 보존 원칙상 임의로 지우지 않았다.
- 현재 채점은 문자열 내부를 보존한 토큰 비교다. 공백·들여쓰기는 허용하지만 서로 동등한 다른 구현/인용부호/별칭까지 판별하지 않는다. 실제 Python 실행 및 전체 노트북 실행 검증은 하지 않는다.
- 별표는 기존 원본 빈칸 메타데이터를 유지했다. 별표 자체가 출제 확률이나 정답의 공식성을 보장하지 않는다.
- RAG의 KG는 강의의 직접 구현/API 연동이며, 전부 LlamaIndex 내장 KG 구현인 것은 아니다. LLM LoRA도 강의의 직접 구현을 사용하므로 PEFT LoraConfig 문제와 완전히 같은 형식은 아니다.

## 모의고사 규칙

- 실제 코드 셀 후보 98개 중 중복 없이 10개 선택한다.
- LLM·RAG·Data·Vision·On-device에서 1셀씩 먼저 선택한 뒤 남은 전체 후보에서 5셀을 추가하고 순서를 섞는다. 정확히 과목별 2셀은 아니며 각 과목 최소 1셀이다.
- 브라우저 crypto 난수를 매번 새로 사용한다. 고정 seed/seed 입력은 없다. 무작위 추첨이므로 이전 회차와 일부 셀이 겹칠 수 있다.
- 선택된 셀의 등록된 빈칸을 모두 숨긴다. 임의의 토큰을 새 빈칸으로 만들지 않으며 회차별 총 빈칸 수는 달라진다.
- 제출 전 정답·해설 비공개. Ctrl+Enter는 다음 빈칸 이동, 별도의 제출 버튼으로 전체 채점한다.
- 셀 점수는 해당 셀의 모든 빈칸이 맞아야 1점. 빈칸별 정답 수도 별도로 표시한다. 셀별 난이도가 같다는 뜻은 아니다.
- 제출 후 답안은 읽기 전용으로 고정하고 정답·해설을 코드 옆에 표시한다. 오답과 미입력은 오답노트에 저장한다.
- 새 회차는 답안을 초기화한다. 진행 중 답안은 새로고침으로 사라지며 홈으로 나갈 때 작성 내용이 있으면 확인을 받는다. 기존 일반 학습의 답안과 별도 상태다.
